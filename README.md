당화혈색소 5.9%(당뇨병 전단계 범위)인 부모님 두 분의 식사와 운동 관리를 돕는 안드로이드용 웹앱입니다.

> **이 문서는 작업 인수인계서입니다.** 다른 날, 다른 기기에서, 새 Claude 세션으로 이어서 작업할 때 이 문서만 읽으면 되도록 정리했습니다.
> 자세한 설계와 의학 근거는 [PLAN.md](PLAN.md)에 있습니다.

### 3-2. 근거 원문 검증 (M0-b) — 네트워크 허용

지금 개발 환경에서는 학술지 원문 사이트가 열리지 않아, 의학 수치를 아직 원문으로 확인하지 못했습니다.

1. Claude에게 "M0-b 원문 검증을 위해 네트워크 허용을 요청해줘"라고 말하면 승인 창이 뜹니다. 내용을 확인하고 승인합니다.
2. 필요할 것으로 예상되는 사이트: `pmc.ncbi.nlm.nih.gov`, `pubmed.ncbi.nlm.nih.gov`, `www.ncbi.nlm.nih.gov`, `doi.org`, `diabetesjournals.org`, `e-dmj.org`, `link.springer.com`, `bjsm.bmj.com`, `www.who.int`, `www.cdc.gov`, `www.heart.org`, `synapse.koreamed.org`, `www.mohw.go.kr`, `www.fao.org`, `academic.oup.com`, `www.sciencedirect.com`
3. Claude가 `src/evidence/registry.ts`의 항목을 하나씩 원문과 대조합니다.
   - 원문과 같으면: `status: 'verified-primary'`로 바꾸고 `quote`(원문 인용), `location`(쪽·표·권고 번호), `checkedOn`(확인일)을 적습니다.
   - 원문과 다르면: 내용을 고치거나 `excluded`로 바꾸고 이유를 적습니다.
   - 결과는 `EVIDENCE.md`로도 정리합니다.

## 4. 부모님 화면 원칙 (IT에 익숙하지 않은 분 기준)

1. **첫 화면은 큰 버튼 2개뿐**: [식사 사진 찍기] [식후 걷기 시작] + 오늘의 한마디 한 줄.
2. **한 화면에 한 가지 일**, 다음 행동은 큰 버튼 하나.
3. **확인은 두 버튼**: AI가 고른 답을 미리 골라 두고 [맞아요] [양 바꾸기]만. 양은 ½·1·1½·2공기 그림 버튼.
4. **글자 입력 최소화**: 이름·숫자 입력은 가족 관리(자녀용) 화면에서.
5. **관리 기능은 분리**: 설정, 검사 기록, 가족 공유, 월간 요약, 요금은 '가족 관리(자녀용)'에만 둡니다.
6. **로그인은 자녀가 처음 한 번**, 이후 자동 유지.
7. **오류는 쉬운 말 + 해결 버튼 하나** (예: "사진이 어두워요" → [다시 찍기]).
8. **전문 용어 대신 비유**: 탄수화물 옆에 "밥 n공기".
9. **알림은 꼭 필요한 것만** (식후 걷기 알림 정도).
10. **부모님이 확인하기 어려우면 '자녀가 나중에 확인'**으로 남길 수 있게 (확인 전 값은 합계에서 제외).
11. **실제로 부모님께 써 보시게 하고 막히는 곳을 고칩니다** (M7 사용성 테스트: 혼자서 1분 안에 한 끼 기록).

## 6. 모든 세션이 지켜야 할 원칙

1. **로컬 PC 파일을 만지지 않습니다.** 코드는 GitHub에 직접 커밋하고, 검사는 GitHub Actions에서 합니다.
2. **원문으로 확인된 근거만 씁니다.** 의학 기준값은 `requireVerified()`로만 꺼내며, 확인되지 않은 값을 쓰면 테스트와 빌드가 실패합니다.
3. **영양소 숫자는 식약처 DB나 제품 표기값만** 씁니다. AI는 음식 인식과 양 제안만 합니다.
4. **사람이 확인한 값만** 합계에 넣습니다.
5. **먹은 만큼 운동으로 갚게 하지 않습니다.** 운동 권장은 지침 범위 안에서만 합니다.
6. **진단, 혈당 예측, 약·영양제 추천은 하지 않습니다.**
7. **비밀값은 저장소에 올리지 않습니다.**
8. **정확도가 우선입니다.** 비용은 정확도에 영향이 없는 방법으로만 줄이고(사진 크기 최적화, 고정 지시문 캐싱, 짧은 응답 형식, 같은 사진 재분석 방지), 모델 변경은 사용자가 결정합니다. 월 상한은 $10입니다.
9. **부모님 화면은 최대한 간결하게** 만듭니다(4장).

## 8. 자동 검사 기록 (GitHub Actions)

- 커밋할 때마다: 패키지 설치 → 타입 검사 → 단위 테스트(근거 등록부 검사 포함) → 배포용 빌드
- 2026-11-27 통과 기록: Node 24.22.3 / npm 11.19.1, react 19.3.1, vite 7.3.8, vitest 3.2.7, typescript 5.9.3, @vitejs/plugin-react 4.7.0, 테스트 6개 통과
- 첫 실행은 Node 22(npm 10)에서 npm 내부 오류(`Cannot read properties of null (reading 'edgesOut')`)로 실패했고, Node 24(npm 11)와 단순한 버전 범위로 해결했습니다. Vercel도 같은 Node 24를 쓰도록 `package.json`에 `"node": "24.x"`를 지정했습니다.

| 명령 | 하는 일 |
|---|---|
| `npm run typecheck` | TypeScript 타입 검사 |
| `npm test` | 단위 테스트 (근거 등록부 검사 포함) |
| `npm run build` | 타입 검사 + 테스트 + 배포용 빌드 (Vercel이 실행) |
